# Pensamento Computacional

> **Trilha:** Fundamentos da Computação · **Status:** estruturando

## Em uma frase

É aprender a decompor um problema grande em partes pequenas o suficiente para que uma máquina — ou uma pessoa — consiga resolvê-las em sequência.

## O que ficou

- Decomposição de problemas
- Abstração: ignorar o detalhe que não importa agora
- Reconhecimento de padrões e generalização
- Algoritmos, pseudocódigo e fluxogramas
- Lógica booleana e tomada de decisão

## Por que isso importa depois

Ninguém programa um sistema inteiro de uma vez. O trabalho real começa justamente onde essa disciplina termina: olhar para um problema confuso, recortá-lo em partes, decidir o que é essencial e só então escrever código. A parte mais valiosa não é a sintaxe — é o hábito de **estruturar o pensamento antes de digitar**. Isso vale para arquitetura de software, para análise de dados e até para organizar a própria rotina.
