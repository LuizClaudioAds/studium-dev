# Engenharia de Usabilidade

> **Trilha:** Engenharia & Produto · **Status:** estruturando

## Em uma frase

Software bom não é o que tem mais funcionalidade — é o que a pessoa consegue usar sem pensar, sem errar e sem desistir.

## O que ficou

- Heurísticas de Nielsen e avaliação de interface
- Personas, cenários e jornada do usuário
- Testes de usabilidade e observação
- Acessibilidade e design inclusivo
- Interação humano-computador e feedback

## Por que isso importa depois

De nada adianta um backend impecável se ninguém entende onde clicar. Usabilidade é o que transforma código em algo que as pessoas **querem** usar. E o hábito de observar alguém tentando usar o que eu construí — sem explicar nada — é o feedback mais honesto que existe. Vale para produto, para documentação e até para apresentação.
